# Git 워크플로우 및 자율 브랜치/커밋/푸시 자동화 규칙

## 1. 커밋 메시지 포맷
모든 Git 커밋 메시지는 아래 형식을 따른다.

```plaintext
<type>(<scope>): <한글 커밋 요약>

[선택적 본문: 변경 이유 및 상세 내용 (한글)]
```

### 허용되는 Type 8종
- `feat`: 새로운 기능 추가 (예: `feat(watchdog): 다중 프로세스 독립 상태 머신 및 서킷 브레이커 구현`)
- `fix`: 버그 및 예외 처리 수정
- `docs`: 문서 및 README 수정
- `refactor`: 기능 변경 없는 코드 구조 개선 및 모듈 분리
- `perf`: 성능 및 메모리 최적화
- `style`: 코드 포맷팅, 스타일 수정
- `test`: 단위 테스트 및 통합 테스트 추가/수정
- `chore`: 빌드 설정, 패키지 의존성, `.gitignore`, 에이전트 규칙 설정

## 2. AI 에이전트 자율 브랜치 운용 및 자동 커밋·병합·푸시 규칙
사용자가 매번 별도로 커밋이나 푸시를 지시하지 않아도, AI 에이전트는 작업 규모와 상황에 맞춰 스스로 판단하여 브랜치 생성, 커밋, `main` 병합 및 원격 저장소(`origin`) 푸시까지 자동으로 완수한다.

1. **작업 규모별 브랜치 전략 자율 판단**:
   - **단순 수정 / 문서 보완 / 소규모 패치 / 초기 스캐폴딩**: `main` 브랜치에서 직접 작업 후 검증 완료 시 즉시 커밋 및 `git push origin main`을 수행한다.
   - **신규 기능 개발 / 대규모 리팩토링 / 다중 모듈 변경**: 작업 성격에 맞는 기능 브랜치(`feat/<기능명>`, `fix/<이슈명>`, `refactor/<대상>`)를 생성하거나 기존 작업 브랜치로 전환하여 단계별로 커밋한다.
2. **검증 완료 후 자동 병합(Merge) 및 푸시**:
   - 기능 브랜치에서 작업이 완료되고 필수 검증(`npm run typecheck`, `npm test`, `npm run build`)을 모두 통과하면, 사용자 추가 지시를 기다리지 않고 자동으로 `main` 브랜치로 체크아웃하여 병합(`git merge --no-ff` 또는 Fast-forward)한 뒤 `git push origin main`까지 완료한다.
   - 병합이 끝난 임시 로컬 브랜치는 필요에 따라 정리(`git branch -d`)하거나 이력 추적용으로 유지한다.

## 3. 저장소 보안 및 대용량 파일 관리
- `.env`, 데이터베이스 파일(`*.db`, `*.db-wal`, `*.db-shm`), 실시간 로그(`logs/`, `log/`), 로컬 참조 문서 폴더(`_ref/`), 대용량 빌드 산출물(`release/`, `dist/`, `out/`, `*.exe`)은 절대 Git에 커밋하지 않는다.
